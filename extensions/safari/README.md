# Safari Web Extension target (not yet added to the Xcode project)

These are the extension-target sources generated by `xcrun safari-web-extension-converter`
(`Info.plist`, `SafariWebExtensionHandler.swift`). The converter cannot add a target to an existing
project, so the target is added by hand in Xcode. The web resources are NOT copied: the target
points at `extensions/send-to-stash-video/`, which is shared with Chrome and Firefox.

## Steps

1. Open `yt-dlp-gui-Macos.xcodeproj`. File > New > Target > macOS > Safari Extension.
   Product Name `Stash Video Extension`, bundle identifier
   `com.ayala.solutions.yt-dlp-gui-Macos.SendToStashVideo`, Embed in Application: `yt-dlp-gui-Macos`.
2. Delete the template files Xcode generated and add `Info.plist` and `SafariWebExtensionHandler.swift`
   from this folder to the new target (do not copy them).
3. Remove the template `Resources` group. Add the folder `extensions/send-to-stash-video` as a
   folder reference (blue folder, not a group) to the target, and make sure it is in the target's
   Copy Bundle Resources phase so `manifest.json` ends up at the top of the appex `Resources`.
   The converter's pbxproj referenced the original folder in place, which is what this does.
4. Set the target's deployment target to macOS 14.0 and Swift language version to 6; sign with the
   same team as the app. Build Release.
5. Safari > Settings > Extensions: enable "Send to Stash Video", click its toolbar button on a page;
   the running app should analyze the URL.
6. Check: `codesign --verify --deep --strict "build/Build/Products/Release/Stash Video.app"`
   (no output, exit 0).

## Signing and notarization

`Scripts/sign-app.sh` signs the app with `codesign --force --deep --entitlements
StashVideo.entitlements`. Once the appex ships, that command is wrong: `--deep` stamps the
app's entitlements onto the nested `.appex` too, replacing the sandbox entitlements an app
extension requires. Sign inside out instead:

1. Sign the appex first with its own sandbox entitlements:
   `codesign --force --options runtime --timestamp --entitlements <appex>.entitlements --sign "$DEV_ID" "$APP/Contents/PlugIns/<appex>.appex"`
2. Then sign the app without `--deep`, with the app's entitlements:
   `codesign --force --options runtime --timestamp --entitlements StashVideo.entitlements --sign "$DEV_ID" "$APP"`
3. Verify with `codesign --verify --deep --strict` and `codesign -d --entitlements - <appex>` to
   confirm the appex kept its sandbox entitlements.

Until this target ships, Safari users should use the bookmarklet.
